# BetBoard

> Виртуальные ставки на дружеские события — без реальных денег.

**BetBoard** — приватная игровая платформа для компании друзей (3–20 человек),
где участники делают прогнозы на внутренние события, используя виртуальные
очки, а не настоящие деньги. Никаких платежей, вывода средств и букмекерства —
только сезонные очки, репутация, титулы и право хвастаться.

Примеры событий:

- кто выиграет партию в настолку;
- кто победит в товарищеском матче 5×5;
- какой фильм выберет группа на вечер;
- кто придёт последним на встречу;
- кто станет чемпионом сезона в дартс;
- какая команда победит в квизе.

Деньги не используются вообще. Только виртуальные очки, репутация и титулы.

---

## Как это работает

BetBoard превращает дружеские споры («я же говорил, что победит Саша») в
систему: прогнозы фиксируются заранее, ставки делают прогноз осмысленным,
результат записывается, история сохраняется, а лучшие предсказатели получают
репутацию.

Главный игровой цикл:

```
PREDICT → BET → RESOLVE → PROFIT/LOSE → BRAG
```

1. Кто-то **создаёт событие** с набором исходов.
2. Друзья видят список исходов и текущие коэффициенты.
3. Участники делают **ставки** виртуальными очками.
4. Событие происходит.
5. Организатор или судья **фиксирует результат**.
6. Очки перераспределяются (пул делится между победителями).
7. Обновляются рейтинги, сезонная таблица и репутация оракулов.

## Ключевые механики

- **Виртуальные очки** — игровая валюта внутри компании (например, 1000 на
  старте сезона). Покупать за реальные деньги и выводить нельзя.
- **Ставки** — прогноз с весом: чем больше очков, тем сильнее уверенность, но
  и больше риск.
- **Коэффициенты** — фиксированные (задаёт создатель) или динамические
  паримутуальные (формируются по пулу ставок).
- **Пул события** — все ставки собираются в общий пул, который делится между
  победителями пропорционально их ставкам.
- **Сезон** — временной период (неделя, месяц, поездка, марафон). В конце
  очки можно сбросить, определить чемпиона и выдать титулы. Помогает избежать
  инфляции очков.
- **Репутация оракула** — отдельная метрика точности, независимая от размера
  банка.
- **Титулы и достижения** — «Оракул», «Холодный расчёт», «Генератор рисков» и
  десятки других игровых наград.

Экономика строится на **паримутуальной модели** (пул делится пропорционально
ставкам на победный исход). Пример: пул 1000 очков, на исход B поставили 300,
из них ваша ставка 50 → выплата `1000 * (50/300) ≈ 166.67`, чистая прибыль
≈ 116.67.

## Стек технологий

Проект задуман как сильное Next.js-приложение с отдельным API.

| Слой        | Технологии                                                        |
| ----------- | ----------------------------------------------------------------- |
| Web         | Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui, Zod    |
| API         | NestJS, Prisma 7 (PostgreSQL), Auth (JWT), Swagger                |
| Клиент-стейт | React Query / SWR, Server Actions, optimistic updates            |
| Real-time   | SSE для live-коэффициентов, polling как fallback                  |
| Инфра       | Vercel (web), GitHub Actions (CI)                                 |

Ключевые принципы реализации:

- Все игровые изменения (ставки, выплаты) — **идемпотентны** и валидируются
  через Zod.
- Каждое изменение баланса пишется в **ledger** (журнал операций), а не просто
  меняет поле `wallet.balance`.
- Критические операции выполняются в **DB-транзакциях** с защитой от гонок.

## Быстрый старт

Требуется: Node.js 20+, PostgreSQL (для API).

### API (`apps/api`)

```bash
cd apps/api
npm install
# настроить .env (DATABASE_URL, JWT_SECRET, ...)
npx prisma generate
npx prisma migrate dev
npm run start:dev      # запуск с watch → http://localhost:3000
```

Документация Swagger доступна по `/docs` после запуска.

### Web (`apps/web`)

```bash
cd apps/web
npm install
npm run dev           # → http://localhost:3000
```

Подробности запуска и настройки — в `apps/api/README.md` и
`apps/web/README.md`.

## Основные бизнес-правила

1. Нельзя ставить после закрытия приёма ставок (проверка и в UI, и на сервере).
2. Нельзя ставить больше, чем есть на балансе.
3. Один пользователь — одна ставка на событие (для MVP).
4. Результат фиксируется только после закрытия ставок (защита от жульничества).
5. Отмена события возвращает все ставки.
6. Каждая операция пишется в `ledgerEntries` в рамках транзакции.

Anti-abuse: чёткое время закрытия ставок до начала события, аудит изменений,
статус `disputed` для спорных результатов с подтверждением админом, rate
limiting на создание событий и ставок, idempotency-key против повторных кликов.

## Модель данных (кратко)

`users` → `groups` → `groupMembers` → `seasons` → `wallets` → `events` →
`eventOutcomes` → `bets` → `ledgerEntries` → `eventComments` → `achievements` →
`userAchievements`.

Центральная таблица — **`ledgerEntries`**: она делает баланс прозрачным,
позволяет отлаживать споры, откатывать ошибки и показывать пользователю
историю операций. Полная схема — в `ABOUT.md`.

---

## Что НЕ входит в MVP

Не делаем сразу (чтобы не перегрузить проект и избежать юридических рисков):

- реальные деньги, платежи, вывод средств, покупку очков;
- интеграцию с букмекерами и спортивными API;
- сложные деривативы и маркетплейс ставок;
- мобильное приложение;
- AI-прогнозы.
